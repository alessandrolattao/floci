# Aurora DSQL

**Protocol:** REST JSON (control plane) + PostgreSQL wire protocol over TLS (clusters)

**Endpoint:** `http://localhost:4566` (control plane), `<cluster-id>.dsql.<region>.localhost.floci.io:5432` (clusters)

Floci runs each Aurora DSQL cluster as a real PostgreSQL 16 database in a Docker container, behind one
endpoint that admits clients the way DSQL does: TLS, an IAM token as the password, and DSQL's
dialect and limits. The answers, messages and SQLSTATEs below were measured on AWS.

## Supported Actions

<!-- floci:actions:start -->
| Action | Description |
| --- | --- |
| `CreateCluster` | Creates a single-Region cluster, `CREATING` until its database answers, then `ACTIVE`; deletion protection is on unless turned off |
| `ListClusters` | Lists the Region's clusters, paginated |
| `GetCluster` | Returns a cluster, its endpoint and encryption details |
| `UpdateCluster` | Changes deletion protection, the KMS key and the multi-Region properties |
| `DeleteCluster` | Deletes a cluster and its database; refused while deletion protection is on |
| `GetVpcEndpointServiceName` | Returns the Region's VPC endpoint service name |
| `PutClusterPolicy` | Sets the cluster's resource policy, with optimistic versioning |
| `GetClusterPolicy` | Returns the resource policy and its version |
| `DeleteClusterPolicy` | Removes the resource policy |
<!-- floci:actions:end -->

`TagResource`, `UntagResource` and `ListTagsForResource` work on cluster ARNs. Cluster identifiers
are 26 characters of lowercase base32, as DSQL's are, and invalid ones are refused with DSQL's
messages.

## Connecting

A cluster's endpoint is `<cluster-id>.dsql.<region>.localhost.floci.io`, port `5432`.
`localhost.floci.io` resolves to `127.0.0.1` on the host, and to Floci inside the containers Floci
starts, so the same endpoint works from both. All clusters share the port: the TLS server name a
client sends picks the cluster, as DNS does on AWS.

TLS is mandatory. The certificate covers `*.dsql.<region>.localhost.floci.io` for every Region and
is signed by Floci's local CA (`GET /_floci/ca.pem`, see [TLS](../configuration/tls.md)), which the
containers Floci starts already trust, so `sslmode=verify-full` works.

The password is an IAM authentication token for the endpoint, generated by the SDKs and the CLI
exactly as for AWS:

```bash
curl -s http://localhost:4566/_floci/ca.pem -o floci-root-ca.pem
export PGPASSWORD=$(AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test \
  aws dsql generate-db-connect-admin-auth-token --region us-east-1 \
  --hostname <cluster-id>.dsql.us-east-1.localhost.floci.io)
psql "host=<cluster-id>.dsql.us-east-1.localhost.floci.io port=5432 user=admin dbname=postgres \
  sslmode=verify-full sslrootcert=floci-root-ca.pem"
```

When Floci runs in Docker, publish `5432` alongside `4566`.

### Authentication

- `admin` signs in with a `DbConnectAdmin` token; every other role with a `DbConnect` token. The
  wrong action is refused with the hint `Wrong user to action mapping. user: <user>, action: <action>`.
- A token is accepted up to 5 seconds past its expiry, as DSQL accepts it; after that the hint is
  `Signature expired: ...`.
- A role other than `admin` signs in only for the IAM role that `AWS IAM GRANT` mapped to it. The
  token's principal is the role behind its credentials (a Lambda function's execution role, an ECS
  task's role with `FLOCI_SERVICES_ECS_TASK_ROLE_CREDENTIALS_ENABLED`, an `AssumeRole` session),
  its ARN with its path.
- The signature is verified like any other Floci IAM token: the `test` key, or a key or session
  Floci issued. With `FLOCI_SERVICES_IAM_ENFORCEMENT_ENABLED`, the principal also needs
  `dsql:DbConnectAdmin` or `dsql:DbConnect` on the cluster ARN.
- Refusals are `FATAL` with DSQL's text and a `Session Id` detail: `08P01` without TLS, `08006` for
  a token refused, `28000` for a role the token cannot sign in as, and `55000` for any database
  other than `postgres`.

## SQL

The database is PostgreSQL 16 at `REPEATABLE READ`, with DSQL's dialect installed in it:

- `CREATE [UNIQUE] INDEX ASYNC` answers a `job_id`; `sys.jobs` and `sys.wait_for_job` report the
  job. A unique index over duplicate keys fails its job with `found duplicate key(s) while validating
  index uniqueness` and stays, invalid, as on DSQL. A plain `CREATE INDEX` is refused.
- `AWS IAM GRANT <role> TO '<role arn>'` and `AWS IAM REVOKE <role> FROM '<role arn>'`, with
  `sys.iam_pg_role_mappings`. A superuser role cannot be mapped, and only a role holding the
  `ADMIN` option on a role can map it: `admin` maps the roles it created.
- One DDL statement per transaction, no DDL with DML, at most 3,000 modified rows per transaction,
  and a transaction older than 300 seconds fails at its next statement. Connections close after an
  hour.
- Refused with DSQL's SQLSTATE and message: temporary and partitioned tables, triggers, `CREATE
  TYPE`, PL/pgSQL functions and `DO`, extensions, array columns, `jsonb` and `bytea` keys,
  `TRUNCATE`, `LISTEN`/`NOTIFY`, `VACUUM`, sequences without a `CACHE` of 1 or at least 65536,
  `ALTER TABLE ... ADD COLUMN` with a constraint or default, `ADD CONSTRAINT`, `FOR SHARE` and `FOR
  NO KEY UPDATE`, advisory locks, and isolation levels other than repeatable read.
- Foreign keys work as on DSQL: declared in `CREATE TABLE`, enforced, with their `ON DELETE` and
  `ON UPDATE` actions and `DEFERRABLE`; rows a cascade changes count toward the 3,000-row limit.
  Adding one with `ALTER TABLE` is refused, as DSQL refuses it.
- Errors carry no source location, as DSQL's carry none; notices keep theirs.
- `sys.iam_session_user()`, `sys.current_session_id()`, `sys.dsql_major_version()`,
  `sys.cluster_size()` and `sys.cluster_size_limit()` answer as on DSQL.

### Differences from AWS

- DSQL is optimistic: conflicting transactions both run and the second to commit fails. Floci's
  database is PostgreSQL, so a write that conflicts waits for the other transaction and fails when
  it commits. The error is DSQL's either way: `40001`, `change conflicts with another transaction
  (OC000)`.
- DSQL accepts connections while a cluster is still `CREATING`; Floci's cluster is `CREATING` only
  while its database starts, and serves once it is `ACTIVE`.
- Clusters are single-Region: multi-Region properties are stored and returned, not replicated.
- `sys` also holds the tables behind Floci's jobs and IAM mappings.
- DSQL's primary key covers every column of its table, and its definition reads `PRIMARY KEY (id)
  INCLUDE (...)`; Floci's reads `PRIMARY KEY (id)`.
- A statement Floci refuses carries no position (`LINE 1: ...` in psql), and a cascade past the row
  limit carries no context naming the statement the cascade ran; DSQL gives both.

## CloudFormation

`AWS::DSQL::Cluster` waits for `ACTIVE`. `Ref` returns the identifier; `Fn::GetAtt` supports
`Identifier`, `ResourceArn`, `Status`, `CreationTime`, `Endpoint`, `VpcEndpoint` and
`VpcEndpointServiceName`. A protected cluster makes the stack's deletion fail, as on AWS.

## Configuration

| Variable | Default | Description |
|---|---|---|
| `FLOCI_SERVICES_DSQL_ENABLED` | `true` | Enable or disable Aurora DSQL |
| `FLOCI_SERVICES_DSQL_MOCK` | `false` | Clusters without a database, `ACTIVE` at once and without Docker: enough for the control plane and CloudFormation |
| `FLOCI_SERVICES_DSQL_PORT` | `5432` | Port every cluster endpoint is served on |
| `FLOCI_SERVICES_DSQL_ENDPOINT_SUFFIX` | `localhost.floci.io` | Domain the endpoints are named under, `<cluster-id>.dsql.<region>.<suffix>` |
| `FLOCI_SERVICES_DSQL_IMAGE` | `postgres:16-alpine` | Image each cluster's database runs in |
| `FLOCI_SERVICES_DSQL_DOCKER_NETWORK` | Floci's network | Docker network for the databases |

A cluster's data lives in a Docker volume of its own, or under the host persistent path, and is
removed with the cluster under the same policy as RDS's (`prune-volumes-on-delete`). With
persistent storage a cluster comes back, with its data, when Floci restarts.

See the [Aurora DSQL API Reference](https://docs.aws.amazon.com/aurora-dsql/latest/APIReference/Welcome.html)
and the [Aurora DSQL User Guide](https://docs.aws.amazon.com/aurora-dsql/latest/userguide/what-is-aurora-dsql.html).
